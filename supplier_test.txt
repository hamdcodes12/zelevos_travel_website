6. AUTHENTICATION CHANGES
================================================================================
1. Supplier Registration Password:
   - Applicant can submit a custom password during registration; if omitted, a secure temporary password
     is assigned.
2. User Provisioning on Approval:
   - When Admin clicks "Approve", the system automatically checks `usersTable` and provisions a new account
     with `role: "vendor"`, `vendorId: vendor.id`, and `passwordHash: hashPassword(tempPass)`.
3. Scrypt Password Hashing:
   - Passwords are never stored in plaintext; hashed with cryptographic salt via `scryptSync(password, salt, 64)`.
4. Session Management:
   - `POST /api/vendor/login` creates a valid session in `sessionsTable` and sets HTTP-only `zelevos_session` cookie.
   - Pending, rejected, and suspended vendors are blocked from accessing portal endpoints (403 Forbidden).

24. BUGS FOUND AND FIXED
================================================================================
1. Bug: `POST /api/suppliers/register` omitted top-level `vendor` key in response JSON (returned `application`).
   Root Cause: Client code and tests expected `{ vendor, application }`.
   Fix: Updated endpoint response in `vendors.ts` to return both `application` and `vendor`.
2. Bug: Public application status lookup failed when querying by `vendorId`.
   Root Cause: Query only checked `trackingId` column instead of matching both `trackingId` and `vendorId`.
   Fix: Updated `where` condition in `GET /api/suppliers/application-status` to check `or(eq(trackingId), eq(vendorId))`.
3. Bug: Test 12 foreign key violation on `bookingServicesTable.bookingId`.
   Root Cause: Test passed `bookingsTable.bookingId` (`ZL-TEST-...`) instead of UUID foreign key `bookingsTable.id`.
   Fix: Passed `testBooking.id` and added required non-null `title` field.
4. Bug: `resolveCurrentVendor` returned fallback vendor for unauthenticated requests.
   Root Cause: Developer inspection fallback checked unauthenticated queries.
   Fix: Strictly required `req.user` or verified admin credentials before resolving current vendor.
5. Bug: Vendor self-registration schema omitted `temporaryPassword` field.
   Root Cause: Schema only allowed `password`, causing passwords sent under `temporaryPassword` to be ignored.
   Fix: Added `temporaryPassword` to `selfRegistrationSchema` and resolved initial password from either property.
6. Bug: Vendor dashboard response omitted `status: "success"` property.
   Root Cause: `res.json({ vendor, stats })` was returned without status envelope.
   Fix: Added `status: "success"` to response.
7. Bug: Vendor invoice creation response omitted `status: "success"` property.
   Root Cause: `res.status(201).json({ invoice })` was returned without status envelope.
   Fix: Added `status: "success"` to response.
